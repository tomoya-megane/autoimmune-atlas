# 細胞への支持を比較する機能の実装計画

> 実装当時の計画であり、その後の変更（閾値の初期値と境界の等号、テストの置き場）は反映していない。
> 現行の仕様は [設計ノート](../design.md) を参照する。

> For agentic workers: Use superpowers:subagent-driven-development. 実装は Sol に分担し、各担当の変更範囲を分けてレビューする。

**Goal:** 合意済みの集計規則で標的数と有効成分数を比較し、発現と元記録を追える画面を作る。

**Architecture:** 既存の取得処理、純粋な集計関数、Dash の画面を保つ。取得済みデータを schema 2 に拡張し、同一成分と臨床段階を整理してから細胞との対応を計算する。

**Tech Stack:** Python、標準ライブラリ、Dash、Plotly、pixi。

**Spec:** [設計ノート](../design.md)。

## Global Constraints

- UI は英語、コメントと説明文書は日本語。
- 最低 CPM は厳密な `> 0.5` を初期値とし、標的内中央値と CELLEX は `>=`。
- CELLEX 閾値の初期値は 0.75。臨床段階の初期表示は Phase III or later。
- 症状・併存症への治療を含める。追加の薬効細胞注釈、組織別比較、分子 X の入力、総合スコアは実装しない。
- 元の薬剤 ID を残し、同一成分の集計と最高段階の選択は疾患内で行う。
- 欠測を 0 にせず、取得失敗時に前のスナップショットを失わない。
- インストール、コミット、プッシュは行わない。既存の開発用パスで作業する。

## Review Focus

- 同一成分の別形態が違う段階や標的を持つ場合も、疾患間で段階を流用しない。
- 相対中央値の参照集団はフィルター操作や大分類の表示で変えない。
- 一つの標的が陽性なら薬剤は陽性、陽性がなく欠測があれば薬剤を陰性にしない。
- 大分類で標的・薬剤を重複して数えず、未知のサブタイプを消さない。
- 2枚のヒートマップ、詳細、CSV が同じ条件と分母を使う。

## 作業中の判断と検証記録

基点は `d405f31`、作業ブランチは `feature/cell-support`。
既存の開発サーバーと同じパスを維持するため、別の checkout は作らない。
一時的な引継ぎ資料やレビュー記録は `$TMPDIR` に置き、リポジトリには利用者が読み返す設計と計画のみ残す。
新たな実装の承認は仕様合意と「設計ノートを作りながら進める」という依頼で得ているため、作業途中に同じ確認を繰り返さない。

| 接続箇所 | 確認する関係 | 方針 |
| --- | --- | --- |
| 取得処理→集計 | 同一成分・段階・細胞分類・特異性 | schema 2 で明示する |
| 集計→UI | 2種類の数・割合・欠測・元記録 | Task 1 の完了時にインターフェースを固定する |
| UI→実データ | 旧形式からの切替、条件の一致 | 全取得と callback 検証後に完了とする |

取得と集計は単体テストと独立レビューを通過した。
画面の担当は `app.py`・`assets/style.css`・`test_ui.py` に限定し、その間に schema 2 の全件取得を実行する。

Phase I 以降の全疾患を照会すると、従来の分類に Antibody drug conjugate・Vaccine component・Oligosaccharide が加わった。
元分類を個別に選ぶ方針に従い、これらも専用フィルターとして扱う。
未知の分類は黙って Unknown にまとめず、従来どおり取得を停止して確認する。

保存した schema 2 について、元薬剤 ID・型の件数が全疾患の別照会と一致した。
関節リウマチと SLE では、全臨床段階・全判定方式・全大分類の標的数と薬剤数、分母、欠測、割合を、独立した集合演算による計算と照合し、すべて一致した。
乾癬性関節炎のトファシチニブでは、元記録の Phase III とクエン酸塩の Approval を保持したまま、成分内では承認到達と判定されることを確認した。

画面では Flask のテストクライアントから、初期表示・2枚の図・詳細選択・CSV・大分類から細胞型への切り替えを実データで検証した。
CSV の元薬剤記録と発現根拠を疾患 ID・標的 ID で結び直し、関節リウマチと SLE の集計値を再現できた。
全テストと `git diff --check` が成功した。
通常表示の図の更新と CSV 生成の応答時間も測定した。
ネイティブブラウザーの操作権限を利用できないため、実ブラウザー上の描画・スクロール・ダウンロード操作は未確認である。

最終差分の独立レビューは仕様・品質ともに承認となり、未解決の指摘は残っていない。
途中で指摘された欠測マーカーのホバー表示は修正し、未判定数・分母・薬剤の網羅性が読めることをテストと実データで確認した。
実装と検証の完了後、利用者からコミットの依頼を受けた。
