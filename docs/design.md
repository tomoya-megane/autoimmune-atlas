# 治療薬標的の発現から細胞への支持を比較する

このアプリは、自己免疫疾患ごとに、臨床開発された薬剤の標的がどの細胞型で発現するかを比較する。
標的分子と作用が分かっている新薬について、適応疾患の仮説を考えるために使う。
ここでいう支持は、臨床開発された薬剤と健常時の標的発現から推定した相対的な対応である。
薬効を担う細胞の確定、臨床的な有効確率、患者組織での発現変化を表さない。

## 比較の対象を同じ条件で絞る

対象疾患は、Open Targets の autoimmune disease (`MONDO_0007179`) と、追加の起点の下位語の和集合とする。
MONDO は idiopathic inflammatory myopathy や lupus nephritis を自己免疫疾患の枝の外に置くので、1 語の下位語では拾えない。
起点の一覧と、1 件ごとの根拠、起点にしなかった候補は[対象疾患の起点](disease-roots.md)にある。
自己炎症性疾患は `autoinflammatory syndrome` を起点にして含め、アレルギー性疾患は含めない。
下位語に遺伝性や感染性の疾患が混ざる起点は、本体だけを入れる。
起点の一覧は `disease_catalog.py` の `SCOPE_ROOTS` にあり、`fetch_data.py` が起点ごとの下位語を取って和集合を作る。
親概念とサブタイプは混在するため、表示する疾患を選択できるようにする。
症状や併存症に対する治療も含め、初期版では治療目的の分類を行わない。

疾患選択は閲覧用の群、疾患ファミリー、個別用語の順に開けるようにする。
疾患ファミリー内では、疾患本体のチェック欄を先に置き、病型や関連用語のチェック欄は `details` の中にまとめる。
`details` の中は、保存した `parent_ids` に従って MONDO の親子関係どおりに入れ子にする。
子を持つ語は、自身のチェック欄を親の階層に置いたまま、直接の子だけを入れた `details` を続けて開けるようにする。
複数の親を持つ語は、より深い親の下に 1 回だけ置き、同じ深さなら名前順で決める。
2 か所に出すと、片方で外したときにもう片方と食い違う。
本体の選択と詳細内の選択は独立させ、一方を外しても他方は残す。
`disease_catalog.py` の `DISEASE_GROUPS` に群と起点の疾患 ID を定義し、保存した `parent_ids` を辿って最も近い起点へ配置する。
距離が同じ場合は定義順を使い、一つの疾患を複数の群で重複表示しない。
表示時は群とファミリーをそれぞれ名称順に並べ、`Other / unclassified` を最後に置く。
起点と同じ疾患を先頭に置き、残りは名称順に並べる。
検索欄とチェック欄は同じ選択を保持し、ヒートマップと詳細の疾患選択欄にもこの並びを使う。
群は閲覧用であり、親子の選択や薬剤数の集計をまとめる単位にはしない。

初期表示には、全身性疾患、関節、神経、内分泌、皮膚、肝臓に加え、筋と血管の疾患を含む10疾患を選ぶ。
関節リウマチ、全身性エリテマトーデス、シェーグレン症候群、多発性硬化症、1型糖尿病は[全米科学・工学・医学アカデミーのレビュー](https://www.ncbi.nlm.nih.gov/books/NBK605868/)でも自己免疫疾患の多様性を示す代表例として扱われている。
これに全身性強皮症、皮膚筋炎、ANCA関連血管炎、天疱瘡、自己免疫性肝炎を加える。
筋と血管の疾患を含めるため、重症筋無力症と Graves 病を皮膚筋炎とANCA関連血管炎に置き換えた。
皮膚筋炎は[NIAMS の自己免疫性筋疾患の研究対象](https://www.niams.nih.gov/labs/mammen-lab)に含まれ、ANCA関連血管炎は[総説](https://pubmed.ncbi.nlm.nih.gov/39004459/)で全身性自己免疫疾患として説明されている。
これは有病率や疾患の重要度による順位ではなく、このスナップショットでの比較例である。

Open Targets は[複数の親と祖先を持つ疾患階層](https://community.opentargets.org/t/fetching-the-disease-ontology-level/1820)を提供している。
その階層は臨床上の病型分類と同じとは限らないため、表示ではサブタイプだけを意味する語を使わず、関連用語を含むファミリーとして扱う。
取得元の版 26.06 では、関節リウマチの子に乾癬性関節炎と強直性脊椎炎が含まれていた。
両疾患を独立した起点に置き、関節リウマチの下には表示しない。
Hailey-Hailey disease と MASS syndrome は病型としての配置を保留し、`UNCLASSIFIED_IDS` で `Other / unclassified` に残す。
親情報がない既存データや、新しく増えた分類先不明の用語も同じ欄に残し、比較対象から落とさない。

`fetch_data.py` は薬剤情報と一緒に疾患の親 ID を保存する。
既存スナップショットには同じ Open Targets の版から親 ID だけを補い、薬剤記録と発現データは変えていない。
分類を保守するときは、起点 ID、全疾患の配置先、独立して表示すべき疾患を確認し、`test_disease_catalog.py` の回帰テストも更新する。

臨床段階は薬剤全体の段階ではなく、疾患と薬剤の組合せで到達した最高段階を使う。
同じ有効成分の記録を統合する場合も、段階の最大値は疾患内で求める。

| フィルター | 含める段階 |
| --- | --- |
| Phase I or later | Phase I、I/II、II、II/III、III、Preapproval、Approval、Phase IV |
| Phase II or later | Phase II、II/III、III、Preapproval、Approval、Phase IV |
| Phase III or later | Phase III、Preapproval、Approval、Phase IV |
| Approval reached | Approval、Phase IV。取得元が承認到達へ集約した撤回歴も含み得る |

Phase I/II は Phase II 以降に、Phase II/III は Phase III 以降に含めない。
Early Phase I、Phase 0、IND、Preclinical、Unknown はこれらのフィルターに含めない。
取得元の `maxClinicalStage` は、Phase IV または Withdrawal の根拠がある場合に Approval へ集約する。
したがって Approval reached は、現在も有効な承認や販売継続を保証しない。
試験中止の有無でさらに選別する機能は初期版には設けない。

モダリティは All に加え、Small molecule、Antibody、Protein、Cell、Gene、Enzyme、Oligonucleotide、Antibody drug conjugate、Vaccine component、Oligosaccharide、Unknown を個別に選べる。
Antibody drug conjugate、Vaccine component、Oligosaccharide は Phase I まで取得範囲を広げたときに見つかったため、Unknown にまとめず個別に扱う。
初期表示は Phase III or later、All、実数とする。

## 標的の広がりと薬剤の蓄積を別々に数える

標的数は Ensembl 遺伝子 ID の重複を除いた数とする。
複合体の構成遺伝子はそれぞれ数えるため、標的複合体や独立した作用機序の数とは一致しない。
同じ経路の標的が複数あっても、独立した臨床的証拠の数とは解釈しない。

薬剤数は、同じ有効成分と確認できる塩や水和物などをまとめた数とする。
取得元の `parentMolecule.id` がある場合はその ID、ない場合は元の薬剤 ID を使う。
名前の似方から同一成分とは推測しない。
元の薬剤 ID、名称、段階、標的、出典は残す。
同じ成分の標的は重複を除いた集合にまとめ、どの元記録が対応するかを追えるようにする。
最高段階は疾患内の全形態から先に求め、その後にモダリティで元記録を絞る。

ある細胞で薬剤の標的が一つでも判定条件を満たせば、その細胞に一剤と数える。
複数の標的が条件を満たしても、同じ薬剤は一度だけ数える。
同じ薬剤は複数の細胞に対応し得るため、細胞間の排他的な配分ではない。

実数と割合を切り替える。
標的割合の分母は、疾患・臨床段階・モダリティで絞った既知標的数である。
薬剤割合の分母は、同じ条件で絞った、少なくとも一つの既知標的を持つ有効成分数である。
分母は細胞ごとには変えない。
標的が判明している薬剤数と全薬剤数を併記する。

未取得・欠測・標的不明は陰性にせず、未判定として保持する。
実数は確認できた陽性の件数とし、陽性がないときは未判定が残っても 0 とする。
未判定が残る実数は下限値として扱う。
ヒートマップの各マスは数値だけを表示し、下限値であることはホバーと詳細に残す。
比較ヒートマップの色範囲は、標的と薬剤で別々に、適用済みの疾患と条件における全大分類と全元細胞の有効値の最小値と最大値に合わせる。
折りたたみ中の元細胞も範囲に含め、行の展開だけで色が変わることを防ぐ。
全値が同じときは下限を 0、上限を少なくとも 1 とする。
色の濃さを異なる表示条件や標的と薬剤の図の間で直接比較しない。
図の注記には、確認できた支持を表示しており、未判定分によって増える可能性があることを示す。
割合では分母に含まれる項目の未判定のみを下限判定に使い、標的不明薬剤は網羅性として別に示す。
陽性がなく未判定が残る場合、割合は NA とする。
全対象が判定できて陰性の場合は、実数と割合を 0 とする。
分母が空の割合は NA とする。
未判定の原因が標的不明薬剤だけの場合、実数は下限値の 0 でも、すべて判定できた既知標的内の割合は 0 になり得る。

## 発現基準を切り替えて結果の安定性を調べる

Open Targets に統合された Tabula Sapiens の、組織をまとめた細胞型別 pseudobulk を使う。
各値はドナー間中央値で、単位は `CPM(pseudobulk sum[counts])` である。
組織別データ、組織と細胞型の組合せ、DICE の TPM は混ぜない。

| 方法 | 標的を採用する条件 |
| --- | --- |
| Fixed CPM | ドナー間中央値が最低 CPM 以上 |
| Fixed CPM + Target-relative median | 最低 CPM 以上、かつその標的の全参照細胞型にわたる中央値以上 |
| Fixed CPM + CELLEX specificity | 最低 CPM 以上、かつ取得元の `specificity_score` が設定値以上 |

最低 CPM の初期値は 0.5、CELLEX 閾値の初期値も 0.5 とし、変更できるようにする。
空の入力欄は初期値に戻して計算し、実際に適用した値を画面に記録する。
初期設定では CELLEX スコアを 0.5 以上とする。
この境界値は、アプリの判定規則として変更できる。
取得元の high ラベルと境界の等号まで一致すると断定しない。

標的内中央値は、保存済み発現データにある全参照細胞型を対象に計算する。
表示中の疾患、細胞、モダリティ、大分類の選択では計算し直さない。
欠測を 0 として埋めず、相対基準を確定できない場合は未判定として残す。
最低 CPM 未満なら、相対値が不明でも採用条件を満たさないことは判定できる。

発現量は支持の重みにせず、標的別の詳細で連続値として表示する。
発現ヒートマップの色は、標的ごとに全元細胞型の `log2(1 + CPM)` を平均と母標準偏差で標準化した z スコアとする。
各セルには、現在適用中の発現判定関数が陽性を返すときだけ白い丸印を重ねる。
標的は全元細胞型の z スコア間の距離を用いた平均連結クラスタリングで並べ、発現が欠測の標的は末尾に置く。
欠測は計算から除き、全値が同じ標的の観測値は 0 とする。
色の範囲は表示中の z スコアの最大絶対値で決め、0 を中心に上下対称とする。
全値が 0 のときは -1 から 1 とする。
異なる疾患の選択間では色の濃さを直接比較しない。
ホバーには z スコアと元の CPM を示す。
この表示用の標準化は発現判定基準と集計値には使わない。
CELLEX スコアと標的内中央値は異なる比較方法なので、方式名と判定条件を常に表示する。

## 大分類からサブタイプへ根拠をたどる

初期表示はすべての細胞の大分類とし、所属する細胞型を展開して比較できるようにする。
Comparison scope には疾患の選択欄だけを置き、細胞の表示はヒートマップで操作する。
ヒートマップの大分類名はボタンとし、押すと元細胞の行を直下に展開する。
展開状態は両方の図で共有し、適用済みの条件で即時に描画する。
細胞分類はアプリの起動時に保持し、比較用の集計結果は直近の条件1組を再利用する。
展開状態を集計条件に含めず、展開時は表示する行だけを選び直す。
集計結果はアプリのインスタンス内に保持し、別のスナップショットで作ったアプリとは共有しない。
折りたたむと配下の元細胞の行を隠し、大分類の行は残す。
行見出しとの位置を保つため、縦軸のズームを無効にし、行高を固定する。
同名の集計と元細胞型は `(group)` と `(source)` で区別し、大分類の集計には展開状態に関係なく全所属細胞型を使う。
取得元の親分類と Cell Ontology の階層を使い、T 細胞全体には CD4・CD8 系も含める。
元の細胞名と ID を保持し、CD8 陽性という名前から細胞傷害性という機能を新たに付与しない。

細胞の表示順は系統ごとに固定する。
大分類は T 細胞、B 系、自然リンパ球、骨髄系などの免疫系を先頭にまとめ、造血・幹細胞、間質・結合組織・血管、上皮・分泌、神経、生殖細胞へ続ける。
これは比較しやすさのための表示順であり、支持の強さや細胞間の距離を表さない。
フィルターや発現閾値を変えても順序を保ち、疾患間の比較を追いやすくする。

細分類は同じ大分類の中で、保存済みの Cell Ontology の祖先情報から親と子孫をまとめる。
CD4 系と CD8 系など、参照データ内で親子関係を確認できる細胞型を連続させる。
複数の親が候補になる場合は決まった順で一つを選び、表示を重複させない。
親子関係を確定できない同階層の細胞型は名前と ID で並べ、未知の大分類も末尾に残す。
分類への所属や集計規則は変えず、両方のヒートマップ、選択欄、詳細の発現図に共通の順序を使う。

大分類の標的と薬剤は、いずれかの所属細胞型で条件を満たしたものの集合とする。
同じ標的・薬剤をサブタイプ数だけ重複して数えない。
発現量をサブタイプ間で足したり平均したりしない。
参照細胞型の分類の細かさが均一ではないため、大分類間の比較が細胞型数にも影響される点を説明する。

標的と薬剤のヒートマップは、`Distinct targets` と `Canonical drugs` の選択で一方ずつ表示する。
切り替えは上部の選択パネルの Display に置き、実数／割合と並べて操作する。
初期表示は `Distinct targets` とし、縦方向の移動を減らして同じ位置で比較できるようにする。
切り替えても疾患・細胞の並びを保ち、フィルターと実数／割合の選択を共有する。
疾患名はヒートマップの上部に表示し、長い名称に合わせて余白を確保する。
クリックまたは選択欄から、寄与した薬剤、標的、臨床段階、発現量、所属細胞型、出典を確認できるようにする。
ヒートマップのクリックを詳細の選択欄へ反映し、詳細はその選択欄を基準に更新する。
フィルター変更後も表示対象に残る選択を維持する。
元記録表は選択ページの10行だけを生成し、表の下でページを切り替える。
判定を満たした標的だけでなく、選択疾患の既知標的について発現値を確認できる詳細を用意する。

## 上部パネルを操作の順序に沿って分ける

上部パネルは、左2/5に疾患の選択、右3/5に薬剤の条件、発現の判定、表示方法、更新ボタンを配置する。
疾患群の一覧は常時表示し、各群は個別に開閉できるようにする。
一覧の高さには上限を設け、長くなった部分は一覧内でスクロールする。
狭い画面では疾患の選択を先頭に縦に並べる。
対象と判定条件を決めてから、その結果を標的数と薬剤数のどちらで見るかを選べるようにする。
各項目はいつでも編集でき、`Update` を押すと上部パネルの設定をまとめて適用する。
入力中は比較図と詳細を保持し、未反映の変更があることをボタンの隣に表示する。
適用済みの設定を一つの状態として保持し、比較図、詳細の選択肢、詳細が同じ設定を使う。
詳細の疾患選択と元記録のページ操作は、適用済みの結果の中で直ちに反映する。
詳細の連続発現図は選択中の疾患と薬剤条件から標的を取り、全元細胞型の発現を示す。
図の高さを細胞型数に合わせ、図内に縦スクロールを設けない。
元記録表は、選択した疾患と薬剤条件に合う記録を対象にする。
元記録表は薬剤記録ごとに1行とし、細胞別発現と発現判定は表示しない。
比較図の集計値は、いずれかの元細胞型で条件を満たす標的・有効成分の重複を除いて数える。

| 区分 | 項目 |
| --- | --- |
| Drug evidence | 臨床段階、モダリティ |
| Expression criteria | 発現基準、最低 CPM、CELLEX の閾値 |
| Comparison scope | 疾患、細胞の大分類と細分類 |
| Display | 標的／薬剤、実数／割合 |

最低 CPM はすべての発現基準に共通とし、CELLEX の閾値は Fixed CPM + CELLEX specificity を選んだときだけ操作できるようにする。
基準を切り替えても入力済みの閾値は保持する。
比較対象を選ぶ欄は折りたたまず常に表示する。
広い画面では上段に Drug evidence と Expression criteria、下段に Comparison scope と Display を横に並べる。
幅の比率は上段を2対3、下段を2対1とし、比較対象の選択欄を広く取る。
狭い画面では4つの区分をこの順序で縦一列に並べる。
Drug evidence、Expression criteria、Comparison scope の項目は広い画面で横に並べ、Display の View と Measure は縦に並べる。
狭い画面では各区分の項目も縦に並べる。

## 説明を判断に使う場所へ置く

画面に常時表示する文章は、項目名、結果、短い操作案内、対処が必要な入力エラーに絞る。
説明は項目や見出しに添えた ⓘ のツールチップで読み、カーソルを合わせる操作とキーボードでフォーカスする操作の両方に対応する。
位置調整と Escape キーの処理には小さな JavaScript を使い、Python サーバーとの通信を待たずブラウザー内で応答する。
臨床段階の適用単位と承認到達の意味は段階の選択欄に、標的数と薬剤数の定義および割合の分母は Display の各項目に添える。
大分類の集計と欠測、下限値の説明は、比較図の見出しから読めるようにする。
アプリの見出しに添えた説明には、疾患間の差は薬剤と標的の構成の違いであり、健常参照データを使うため疾患別の発現変化や治療効果ではないことを明記する。

発現の条件を満たす記録は、薬効の根拠と混同しない名称で表示する。
CPM はドナー間中央値として表示し、生カウントと誤読される Raw CPM という呼び方は使わない。
値が表示できない理由は、疾患データの未取得、割合の分母がない場合、発現や標的の情報不足をホバーで区別する。

概要の件数には保存済みデータ全体の値であることを示し、フィルター後の件数と区別する。

## 初期版の範囲を保つ

画面は英語、コードのコメント・docstring・設計ノートは日本語とする。
Dash と Plotly、現在の pixi 環境を使い、新しい依存パッケージは導入しない。
起動時は保存済みスナップショットを使い、再取得が全件成功したときだけデータを置き換える。
大容量の `data/` は Git で追跡せず、別環境では `pixi run refresh` で新たに取得する。
取得日時と取得元の版は環境ごとのスナップショットに保存し、結果を比較するときに確認する。
旧形式にない段階や特異性を、推測で補完した完成データとして扱わない。

分子 X の入力と横並び比較、組織別の比較、治療目的の分類、薬効細胞の手作業注釈は今回実装しない。
新たな総合コンフィデンススコアや臨床有効性の確率も作らない。

## 根拠と仕様の対応を残す

- [Open Targets: baseline expression](https://github.com/opentargets/platform-docs/blob/main/target/baseline-expression.md)：pseudobulk、ドナー間要約、CELLEX の定義。
- [Open Targets: clinical report](https://platform-docs.opentargets.org/drug/clinical-report)：臨床段階、元資料、品質管理。
- [Open Targets: drugs and clinical candidates](https://platform-docs.opentargets.org/disease-or-phenotype/drugs)：疾患内の最高段階と撤回歴の承認到達への集約。
- `fetch_data.py`：実際の取得項目と検証、`atlas.py`：集計規則、`app.py`：表示。

設計の変更理由と検証結果は、[作業計画](plans/2026-09-22-cell-support.md)にも記録する。
